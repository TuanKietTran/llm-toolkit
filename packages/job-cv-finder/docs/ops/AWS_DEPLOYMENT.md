# AWS deployment

One small host, **on demand (not always on)**, as the application was built (SQLite WAL, one core, stateless workers; ADR-0002). No RDS, no Kubernetes, no load balancer.

```text
GitHub Actions (OIDC, environment aws-prod)
   test -> infra (terraform plan+apply) -> images (arm64 build, Trivy, ECR push) -> deploy (SSM Run Command) -> verify -> journey
                                                                        |
Cloudflare DNS (DNS only) --> Elastic IP --> t4g.small, Amazon Linux 2023 (default VPC, SG: 80/443)
                                              |- Caddy        TLS (Let's Encrypt HTTP-01), /metrics and /internal/* blocked
                                              |- core         Go, SQLite on a separate encrypted EBS volume (/var/lib/jcf, XFS)
                                              `- intel        Python worker, talks to core over the compose network
                                S3 versioned bucket  <- 6-hourly WAL-safe .backup (integrity checked), 35-day lifecycle
                                EBS snapshots (DLM)  <- daily, 14 kept
                                CloudWatch Logs /jcf/app, alarm on status checks -> SNS topic
```

## Identity and trust

- Account-side identity is the `jcf-bootstrap` CloudFormation stack (`deploy/aws/bootstrap/jcf-bootstrap.cfn.yaml`): role `jcf-deploy-llm-toolkit`, the `jcf-boundary` permissions boundary and three deploy policies scoped to `jcf-*` names and `Project=jcf` tags. It was applied by the owner in the console; the deploy role cannot edit it (explicit deny).
- The role trusts the account's GitHub OIDC provider for exactly one subject. This repository has **immutable OIDC subjects** enabled, so the subject is `repo:<owner>@<owner id>/<repo>@<repo id>:environment:aws-prod`. Read it with `gh api repos/<owner>/<repo>/actions/oidc/customization/sub` (`sub_claim_prefix`) and pass it as the `GitHubSubjectPrefix` stack parameter.
- The workflow assumes the role only in jobs that declare `environment: aws-prod`. The environment accepts deployments from `main` only (see "Branch policy" below).
- No long-lived AWS keys exist. Terraform state lives in the account's state bucket under the `llm-toolkit/` prefix with S3 native locking.

| variable | `AWS_ROLE_ARN` | deploy role ARN |

| variable | `JCF_HOSTNAME` | public hostname Caddy serves |

Branch policy: `main` only. During bring-up the feature branch was also allowed; remove it with
`gh api -X DELETE repos/<owner>/<repo>/environments/aws-prod/deployment-branch-policies/<id>` (list ids with `.../deployment-branch-policies`).

## Environment variable reference (host)

Written by `deploy.sh` from SSM parameters under `/jcf/env/` into `/opt/jcf/core.env` (core) and `/opt/jcf/worker.env` (worker only gets its token and model settings). Never printed.

| Variable | Where | Notes |
|---|---|---|
| `JCF_API_TOKEN` | core | from the GitHub secret through Terraform (SecureString) |
| `JCF_WORKER_TOKEN` | core, worker | random, generated by Terraform |
| `JCF_SECRET_KEY` | core | random 32 bytes (base64), encrypts stored platform credentials. **Keep it**: without it stored credentials cannot be decrypted |
| `JCF_GREENHOUSE_BOARDS`, `JCF_LEVER_SITES`, `JCF_DISCOVER_EVERY` | core | discovery configuration |
| `JCF_MODEL_BASE_URL`, `JCF_MODEL_ID`, `JCF_MODEL_API_KEY` | worker | optional OpenAI-compatible endpoint; not configured (template generation is used) |
| `JCF_HOSTNAME` | Caddy | not passed to the core |

## Deploying

Normal path: push to `main` (paths under `packages/job-cv-finder/` or the two workflows). The workflow plans and applies Terraform, builds both images natively on an arm64 runner, scans them (Trivy, HIGH and CRITICAL fixable findings fail the build), pushes immutable `sha-<12 chars>` tags to ECR, and ships the host bundle plus the release over SSM. `deploy.sh` takes a pre-deploy backup, starts the new pair, waits for the core health check and **rolls back to the previous image pair automatically** if it does not become healthy.

Manual run: `gh workflow run job-cv-finder-deploy.yml --ref main` (add `-f skip_public_check=true` only before DNS exists).

First-time DNS: the workflow prints the Elastic IP in its summary. Create a **DNS-only** (not proxied) `A` record for `JCF_HOSTNAME`. Caddy requests the certificate by itself once the name resolves.

## Host access

There is no SSH and no key pair. Use SSM Run Command (the workflow does) or Session Manager from the console as the account owner. Useful commands, run through `aws ssm send-command --document-name AWS-RunShellScript`:

```sh
docker compose --env-file /opt/jcf/compose.env -f /opt/jcf/docker-compose.yml ps
docker compose --env-file /opt/jcf/compose.env -f /opt/jcf/docker-compose.yml logs --tail 100 core
/usr/local/sbin/jcf-backup                 # backup now
/usr/local/sbin/jcf-restore verify         # restore the newest backup into a scratch dir and check it
```

Logs are also in CloudWatch group `/jcf/app` (30 days).

## On-demand power

The host is normally **stopped**. Stopping keeps the data volume, snapshots, S3 backups and the Elastic IP; a start brings the same containers and database back (restart policy `unless-stopped`, Docker enabled at boot), and Caddy keeps its certificate.

```sh
gh workflow run jcf-power.yml --ref main -f action=status   # status | start | stop
```

`start` waits until `https://<hostname>/readyz` answers 200. While stopped, the 6-hourly backup timer and the daily snapshot of an idle volume do not produce new data; the existing backups remain. A deploy (push to `main`, or `gh workflow run job-cv-finder-deploy.yml`) starts a stopped host, deploys, verifies, and **stops it again** (job `restore-power`, which also runs if an earlier job failed). A host that was running when the deploy began is left running.

## Cost (estimates, not measured)

Stopped: the 20 GiB data volume and 16 GiB root volume (gp3, about US$3), the public IPv4 address (about US$3.6; an Elastic IP bills whether or not it is attached), snapshots and S3 backups (cents). Roughly **US$7/month idle**. Running adds the t4g.small, about US$12/month, billed per second. To remove the address charge as well, release the Elastic IP and re-create the DNS record on the next start (not done: it would change the IP on every start).
